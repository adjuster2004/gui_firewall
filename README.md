# Рубеж — GUI управления фаерволом

Веб-приложение для управления правилами фаервола на удалённом Linux-сервере по
SSH. Бэкенд на **FastAPI + paramiko**, фронтенд — одна HTML-страница. Приложение
само определяет, какой инструмент установлен на сервере (**iptables**,
**iptables-nft** или **nftables**), и работает с ним.

## Возможности

Экран **Правила** показывает цепочки INPUT / FORWARD / OUTPUT в виде таблицы со
столбцами Название · Источник · Назначение · Протокол · Действие · Вкл./Выкл.
Строки перетаскиваются за рукоятку — порядок задаёт приоритет (правила
применяются сверху вниз). Есть добавление, редактирование, удаление, поиск и
включение/выключение правил. Правила, которые не раскладываются на столбцы
(conntrack, интерфейсы, переходы в кастомные цепочки), показываются как
«custom» и переносятся без изменений — ничего не теряется.

Изменения копятся в модели «желаемого состояния» и не трогают сервер, пока вы не
нажмёте **Применить**. Кнопка **Показать команды** выводит точный набор команд.
Применение **атомарное** (`iptables-restore` / одна транзакция `nft -f`), перед
ним снимается резервная копия, при ошибке — автоматический откат.

Экран **NAT** (таблица `nat`): правила **MASQUERADE** и **SNAT** (цепочка
POSTROUTING) выпускают локальную сеть в интернет, **DNAT** (цепочка PREROUTING)
пробрасывает входящий порт на внутренний хост. Правила перетаскиваются, форма
подстраивается под выбранный тип. Filter и nat применяются одной атомарной
транзакцией `iptables-restore`.

Форма filter-правил поддерживает **интерфейсы** (`-i`/`-o`) и **состояние
соединения** (`-m state`/`-m conntrack`, напр. `RELATED,ESTABLISHED`), так что
типовые правила шлюза собираются целиком в GUI.

Экран **Настройки**: параметры SSH (хост, порт, пользователь, ключ или пароль),
**sudo** (пароль или NOPASSWD), порт веб-интерфейса (**8555**), авто-определение
или ручной выбор бэкенда, режим применения (сухой прогон / сразу), сохранение
правил (`netfilter-persistent`) и резервное копирование.

> В корне папки лежит `index.html` — офлайн-прототип интерфейса (без бэкенда,
> демо-данные). Его можно открыть двойным кликом, чтобы быстро посмотреть дизайн.
> Рабочее приложение запускается через `start.bat` / `start.sh` (см. ниже).

## Быстрый старт

Требуется **Python 3.10+**.

**Windows:** двойной клик по `start.bat` (или в консоли `start.bat`).
**Linux/macOS:** `./start.sh`

Скрипт сам создаст виртуальное окружение, поставит зависимости и запустит сервер.
Откройте в браузере **http://localhost:8555**.

### Демо-режим без сервера

Чтобы посмотреть приложение целиком, не имея Linux-сервера под рукой:

```
start.bat --demo        # Windows
./start.sh --demo       # Linux/macOS
```

В демо-режиме правила живут в памяти, реального SSH-подключения нет.

### Запуск в Docker

Нужен установленный Docker с Compose. Из папки проекта:

```
docker compose up -d --build
```

Приложение поднимется на **http://localhost:8555**, настройки и правила
сохранятся в volume `rubezh-data` (переживают пересборку контейнера).

Вход по **SSH-ключу**: compose монтирует `~/.ssh` внутрь контейнера только на
чтение, поэтому в настройках можно указать путь `/root/.ssh/id_ed25519`. На
Windows поправьте строку монтирования в `docker-compose.yml` на
`${USERPROFILE}\.ssh:/root/.ssh:ro`. Вход по паролю работает без монтирования
ключей.

Демо-режим в контейнере — раскомментируйте `RUBEZH_DEMO=1` в `docker-compose.yml`
(или запустите `docker compose run -e RUBEZH_DEMO=1 --service-ports rubezh`).

Остановить: `docker compose down` (данные в volume сохранятся;
`docker compose down -v` удалит и их).

### Первое подключение

Откройте вкладку **Настройки**, укажите хост, пользователя и способ входа
(SSH-ключ рекомендуется), при необходимости включите sudo, нажмите **Проверить
подключение**. После успешного подключения приложение считает текущие правила
сервера и покажет их на вкладке **Правила**.

## Структура проекта

```
backend/
  run.py                 запуск uvicorn (порт из настроек)
  app/
    main.py              FastAPI: API + раздача фронтенда
    api.py               HTTP-эндпоинты
    manager.py           состояние сессии, применение
    models.py            модели данных (pydantic)
    store.py             хранение настроек и правил (~/.rubezh)
    ssh_client.py        SSH + sudo (paramiko)
    firewall/
      detect.py          определение бэкенда на сервере
      iptables.py        чтение/генерация/применение iptables
      nftables.py        то же для nftables (nft)
      demo.py            демо-бэкенд в памяти
frontend/
  index.html             интерфейс (fetch к API)
requirements.txt
start.bat / start.sh     запуск без Docker (venv)
Dockerfile               образ приложения
docker-compose.yml       запуск в контейнере
```

## Безопасность и хранение

Настройки и пароли хранятся локально в `~/.rubezh/` на машине, где запущено
приложение, и по сети уходят только на целевой сервер по SSH. В браузер пароли не
отдаются. По умолчанию сервис слушает `0.0.0.0:8555` — если приложение доступно из
сети, ограничьте доступ файрволом или смените `bind_addr` на `127.0.0.1` в
настройках.

## Замечания по бэкендам

`iptables` и `iptables-nft` поддержаны полностью: таблица `filter`
(INPUT/FORWARD/OUTPUT) и таблица `nat` (PREROUTING/POSTROUTING). Кастомные
цепочки, политики и нераспознанные правила сохраняются без изменений. Бэкенд
`nftables` пока работает только с таблицей `inet filter` (базовые цепочки) и
помечен как бета; управление NAT для него не реализовано — используйте
iptables/iptables-nft. Перед применением на боевом сервере смотрите «Показать
команды».
